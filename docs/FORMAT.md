# 配置处理与边界

## 数据来源

开发依据是本机已有的配置解码实现和 ARM64 库的静态分析。1.7 起取消固定游戏版本号门禁，改为认证材料定位、配置认证与目标字段结构检测。游戏包内库和 `UserGameplay.ini` 仅用于读取校验所需的数据。对从其他设备取得的配置，必须使用该设备配套的 `UserGameplay.ini`。

应用仅修改 `Engine.ini` 和 `Game.ini` 中已定位的目标设置。设备校验文件、库文件、游戏 APK 和脚本不在写入范围内。

## 多发行版目标（1.10）

目标白名单包括国服 `com.tencent.tmgp.dfm`、Level Infinite 国际服 `com.proxima.dfm`、Garena 国际服 `com.garena.game.df`。每次只操作选中的包；安装身份、外置配置路径、材料缓存、备份清单与快照均绑定该包。国际服没有实际配置样本，本版提供安装识别和当前协议的自动兼容检测。配置相对目录或字段结构不匹配时停止并报告；不将国际服包名识别成功等同于配置兼容验证成功。

国服保留原备份目录；国际服使用按包隔离的备份命名空间。切换发行版后，旧快照不能提交给新目标，备份也不能跨目标还原。

Level Infinite 官网 APK `1.202.37117.5602 / 2217` 的项目名为 `DeltaForce`。按范围提取的 ARM64 库可被本版唯一定位，代码与材料采用 XOR `0x5f`。使用国服配套配置对照时，定位材料能够完成双重认证；该检查验证国际库结构和共享材料识别，未验证国际服自己的配置或设备表现。Garena 尚无库和配置样本。

## 加解密流程

1. 记录实际游戏版本、安装更新时间及库来源，验证 ARM64 ELF 结构，读取设备校验配置。
2. 从库中的既定数据及 `UserGameplay.ini` 推导当前设备的配置密钥。
3. 解开 `Token` 的 Base64 封装，分离认证信息和密文。
4. 按该游戏版本的 AES-256-ECB 和填充规则解密，检查配置头、数据长度及 HMAC-SHA1。
5. 按该版本的字符转换规则还原正文，只修改选中的帧率、画质和渲染相关字段。
6. 重新构造认证数据、加密并封装；再次解码校验得到的配置，应与预期正文相符。

所有验证都必须在写入之前完成。验证失败时保留原配置，不使用“忽略错误后继续”的路径。

## 写入与回退

应用保存原始字节及校验摘要，不会自动停止目标游戏。运行中的游戏可能在最后一次摘要检查后或提交后改写配置，现有检查不能完全消除并发保存窗口。写入完成后重新读取实际文件，核对字节和配置认证结果。备份按一次操作的原始配置配对保存，不把备份文件混入游戏目录。恢复时也必须核验备份，避免将其他设备或损坏的文件写入。

本工具不常驻监控游戏配置，不在游戏运行期间反复覆盖配置，不修改资源表中的画质与帧率组合规则。因此配置通过本地校验后，游戏仍可能依据资源表、设备条件或服务器下发设置重新调整。终极画质的独立帧率上限未在本工具中解除。

## 原生分辨率

应用提供渲染比例请求，不修改物理屏幕模式。25%～99% 依赖显示基准的短边像素计算；Android 显示尺寸不一定等于游戏 Surface 尺寸，可手动校准。100% 使用已研究配置中的 8192 请求并依赖游戏 Surface 尺寸夹紧。应以游戏实际渲染尺寸验证，而不能只看文件中填写的数值。

## 已有验证的边界

离线真实样本基线为 1.201.37117.67 / 2207，ARM64。1.7 对新库先尝试已知位置；若认证失败，则依据 ELF 可执行区中的 ARM64 指令形态重定位材料地址，支持已识别的原始与 XOR 包装代码。扫描具有读取总量和候选数量限制。候选须同时通过校验配置和主配置认证，主配置还须符合目标字段结构。

1.8 增加 1.201.37119.49 / 2362 的配套库与配置离线验证。该库的认证材料初始化代码为明文 ARM64，材料采用 XOR `0x10` 存储；此前的 `0xe2` 和原始编码继续支持。首次识别与偏移缓存回读采用相同的三种材料编码范围，每个候选均执行原有 Hash 与 Engine HMAC 认证。写入结果还须通过配置结构与加密回读核对。

1.9 将上述同类编码识别推广至全部 256 种单字节 XOR：代码编码由指令标记推断，并核对完整材料装载结构；数据编码按已知编码优先枚举，用配套 Hash 和 Engine HMAC 认证选择。代码扫描仍限制为 512 MiB、最多 64 个结构候选。每次缓存编码探测、每次 ELF 识别各有 64 MiB 的认证输入预算，按 Hash 字段字节数累计扣除；超限停止当前读取，不再换来源重试。已通过 HMAC 的配置若出现未知认证头或摘要格式，同样直接报告格式错误并停止该次探测。

本机缓存只增加已认证编码的数字提示，安装身份和材料偏移仍参与绑定。下次读取优先使用该提示，提示过期时按相同候选列表探测；候选材料和派生密钥在使用后清空。可自动覆盖的变化包括已识别结构下的偏移与单字节编码变化；认证协议或字段语义变化时仍需继续分析。

这种检测覆盖库重定位及沿用原协议的版本；目标字段的数值映射继续采用已研究规则。协议、函数指令形态或字段映射发生变化时需要继续分析。游戏内帧率与渲染效果仍按设备和游戏实际运行结果核对。

备份使用实际版本及安装身份；旧版备份仅在所属游戏版本和当前认证上下文一致时允许还原。游戏在读取、备份或提交间升级时停止处理，保留必要事务记录供同一安装环境恢复。


## 恢复默认画质设置（1.4）

只删除本工具可以覆盖的本地字段，让游戏启动时重新执行设备默认选择，不写入跨设备固定的档位值。Engine 删除 DFMPerfGearConfig 的 DFMQualityLevel、DFMFPSLevel；QualityFPSSetting 的 Unlimit；SystemSettings 的 PerfGear.SmallPadSize 和 DFMDeviceFrame.White90fps/White120fps/White144fps/White165fps/White185fps。Game 只删除 /Script/PerfGear.PerfGearAndroidPadSizeConfig 的 SmallPadConfig、MidPadConfig、BigPadConfig。

所有同名匹配覆盖会删除（包括重复项）；其他节、字段、注释、换行、Game UTF-8 BOM 及 Engine 外层认证封装格式保留。认证上下文 UserGameplay 不写。重置前自动备份，复用原事务与回读认证流程，可通过“还原最近备份”撤销。无覆盖时不写。该操作清除的同名字段可能原先也是用户手动选择的值；它不是还原某份历史快照，也不重置账号或全部游戏数据。默认档位显示为待游戏生成，不伪装成流畅或60帧。
