# 错误报告说明

1.10 的错误报告绑定当前所选发行版。未安装目标时报告该发行版未安装；切换后需要重新读取配置。国际服首次读取依次验证路径、ARM64库、配置认证和字段结构，未识别的格式会在相应阶段停止。备份所属包与当前目标不同或仍使用旧目标快照时，禁止恢复和提交。

1.7 增加版本兼容性阶段：认证材料定位、校验配置认证、主配置认证、目标字段结构以及安装身份核对。材料能够认证校验配置而主配置 HMAC 失败时，报告配套配置不匹配；库布局或结构无法识别时，报告对应的定位或结构阶段。游戏升级后使用旧快照、跨游戏版本还原会在安装身份核对时停止。

1.8 修复游戏 1.201.37119.49 的库材料编码识别：该版本采用 XOR `0x10`，1.7 只尝试原始与 XOR `0xe2`，会在已经定位 ARM64 候选后报告 HMAC 未匹配。修复同时覆盖首次定位和偏移缓存回读，认证失败仍停止读取或写入。

1.9 可识别同类单字节编码变化，并限制枚举认证的总字节预算。“认证材料编码探测超过 64 MiB 校验预算”表示输入触及认证探测上限，本次操作保留原配置；偏移缓存中的编码提示也不能跳过认证或延长预算。

候选已通过 HMAC、但认证头或摘要正文格式不受支持时，直接报告对应格式错误，不将它误报为错误编码后继续扫描。编码探测只提取一次 Hash 字段，避免对整个配置反复解析。

1.4 起，当前错误界面为简短报告：不显示目标文件、绝对路径、备份位置和详细原因链。操作、阶段、原因、退出码、写入和回滚状态仍保留。完整脱敏报告仅保存本机日志，通过“查看错误日志”主动打开。成功操作会清除当前错误；已提交成功后仅刷新失败时记录日志并保持成功状态。

以下说明完整日志结构。

1.2 起，读取、预览、写入、还原和自动事务恢复均使用同一错误报告。报告包含操作、失败阶段、目标文件、底层原因、可获得的退出码、写入状态、回滚状态、备份位置及建议。

## 阅读顺序

先看“写入状态”和“回滚状态”，再看“阶段”“目标文件”和“原因”。报告可能同时包含安装目录库与 APK 库、两条外置文件路径、原始失败与回滚失败；这些其他尝试会在详细原因链中保留。

- “未写入游戏配置”：此次尚未提交目标文件；可能已经检查权限、建立备份或暂存文件。
- “可能已部分写入”：不能确认两个配置均已提交，应检查回滚是否完成及原件备份位置。
- “自动回滚成功”：原配置已经恢复并通过回读校验。
- “已还原游戏配置，但回滚收尾失败”：配置字节与权限已恢复，事务记录或临时文件仍需处理。
- “配置已写入并校验通过；后处理失败”：目标配置已提交，错误发生在备份索引、同步或清理等阶段。
- “写入已完成，但刷新失败”：写入已经成功，随后重新读取显示状态时发生错误；不能将其当成没有写入。
- “提交标记结果待确认”：配置字节已替换并检查，但提交标记的重命名或同步未确认；保留事务记录，后续读取依据实际记录恢复。

## 文件检查退出码

以下是本工具主动检查路径时返回的代码，不是游戏或 Android 通用错误码。

| 代码 | 含义 |
| --- | --- |
| 44 | 文件不存在，或在本应用当前 root 挂载命名空间中不可见 |
| 45 | 路径不是普通文件 |
| 46 | 文件不可读 |
| 47 | 路径为符号链接，为避免误写已拒绝操作 |
| 48 | 暂存目标已存在，拒绝覆盖 |
| 49 | root 进程不再具有 UID 0 |
| 50 | 挂载命名空间偏离已验证环境 |
| 51 | 所有支持的 root 文件访问路径均验证失败 |

如果通过 ADB 的 root 能看到文件，但本应用报告 44，两者可能处于不同挂载命名空间，或受到应用数据隔离影响；不能仅凭这个代码断定手机上没有该文件。

## 报告保存

失败时自动打开可滚动、选择文字的“本次错误”。“复制报错”复制简短报告；“查看错误日志”及“复制日志”用于完整历史。私有目录 `error-history.log` 最多约 512 KiB；旧版 `last-error.txt` 迁移一次后删除，不在启动或成功后再次呈现旧错。

报告不附完整 shell 命令、配置正文或输入字节。敏感字段值、长认证串、账号及手机号会遮蔽。只有用户主动点击复制时才写入剪贴板；应用不联网发送报告。
